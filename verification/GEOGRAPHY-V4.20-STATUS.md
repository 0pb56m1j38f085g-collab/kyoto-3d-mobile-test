# v4.20 — 地理的な左右・方角・清水寺の主役化

## ユーザーからの実機指摘

IMG_8358.jpeg（南が上の比較地図）とIMG_8359.jpeg（v4.19実機画面）を確認。
誇張は許容されるが、川や名所の実際の位置関係を入れ替えてはいけない。
清水寺を主役にし、重複する下部の名所選択メニューを撤去する。

## v4.19で見落としていた問題

- 元資料の座標は東 +X / 北 +Z。これを上 +Y の右手系3Dへ直接渡したため、
  地理的な左右が鏡像になっていた。北が画面下なのに東が右に見える状態。
- 水系は大まかな東西関係を意識した作図で、地理座標からの投影ではなかった。
  鴨川を街に近づけすぎていた。旧版の「大まかな関係のみ保持」は精度の保証ではない。
- 高台寺・八坂神社などに別々の基準点・独自オフセットを使っていた。
- 390×844の検査だけでは、実機Safariの短い表示領域での建物切れを検出できなかった。

## 対応方針と実装

- 地理資料は変更せず、表示位置に共通の変換（東方向0.42、北方向0.55）を適用。
  建物だけをその地点の周囲で拡大する。東西・南北の順序をテストする。
- 表示の最後にZを一度反転し、東 +X / 上 +Y / 南 +Z の右手系へ変換。
  頂点・法線・三角形の表裏・回転・植栽の接地点・表示メタデータをまとめて変換。
- 初期表示は北側から南を見る。上が南、右が西。北の矢印は画面回転に追従。
  方位ボタンで北を上にできる。建築自体をカメラ向きに勝手に回転させない。
- 清水寺本堂・舞台・西側アプローチの既存形状を保持し、拡大率3.35→5.8。
  ほかの名所を残しながら、清水寺の面積と高さの存在感を優先。
- 下部メニューをHTMLから撤去。4名所のピンを直接押して拡大し、既存の戻すボタンで全景へ。
  画質設定・軽量表示の診断はヘルプへ集約。
- 実際の建物の外周と河川を使ったカメラ調整。390×660の短いSafari相当画面も検査対象。
- iPhoneの照明ファイル取得省略、分割アップロード、CPU形状解放の保護は維持。

## 河川・橋・西側街区の根拠

OpenStreetMap APIの公開地理データを2026-10-22取得。
URL: https://www.openstreetmap.org/api/0.6/map?bbox=135.770,34.993,135.776,35.006

Overpassの2つの取得先は406応答・タイムアウトで利用できず、OSMの標準map APIで取得。
抽出結果: `area-data/west-gion-reference.json`。
再現スクリプト: `area-data/prepare-west-reference.cjs`（保存済みXMLを入力しJSONを標準出力）。
編集者名等は保存せず、出典URL・入力SHA-256・way ID・座標を保存。

- 鴨川: way 254080497。
- 白川: way 550582581 / 623354044 の開水路。623354040は暗渠なので水面表示から除外。
- 四条大橋: way 28322073。中心と向きは元データ、見た目の幅・長さは誇張。
- 西側街区: 出典建物の中心・主要辺方向と街路。個々の町家の実寸・外観再現ではない。
